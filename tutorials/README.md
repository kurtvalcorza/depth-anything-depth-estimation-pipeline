## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`, depth obligations; Kaggle T4 clean run recorded) predicted a synthetic ramp and reported a `not-measurable` verdict because it had no ground truth. This notebook keeps the inference contract as Section 5 — on a real DIODE view with laser-scanned metric depth, so `evaluation_report` returns `sample-sanity` for the first time — and adds the adaptation contract around it: a real RGB-D corpus pinned per file, aligned AbsRel and δ1 in the carried `metrics.py` with the constant and vertical-gradient priors the old report only named, a three-policy ladder (zero-shot, neck and head, bounded unfreeze) selected on validation, before/after depth maps, and an artifact that reloads. `pipe.evaluate` is the labelled corpus-level stage (`measured` / `measured-small-sample`). The `SHOULD` deviation recorded for the old notebook (EVAL11, no trivial baseline) no longer applies.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports) — the 40-row pinned view table travels inside the carried `samples.py` — Section 3 carries the 4-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry; `DepthAnythingPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads with `local_files_only=True` and `trust_remote_code=False`; no cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `urllib`, the model or the processor directly.
- **Data (DAT1–DAT9, ST6):** the default sample is 120 pinned objects — for each of 40 DIODE views the RGB PNG, `_depth.npy` and `_depth_mask.npy` from `huggingface.co/datasets/obukhovai/marigold_depth_eval` at commit `30c5b061`, 312,448,846 bytes in total, one SHA-256 each — DIODE's own files (CC BY 4.0), each refused on any mismatch before it is decoded, and drawn by a seeded shuffle of whole scans into 24 / 8 / 8 views (`check_split_disjoint` asserts no shared view by decoded-pixel digest and no shared scan; `scan_summary` reports scans and domains per split). The template adds a second *External access* bullet naming the host, the commit, the byte count and the licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + `scan_summary` + refusal probes (validation, with three digests) → `validate_inputs` + `pipe.predict` with sanity checks + `evaluation_report` against the view's metric reference (inference contract, `sample-sanity`) → `prior_baselines` + `pipe.evaluate` on the untouched checkpoint (priors and the zero-shot policy) → `pipe.adapt(trainable_blocks=TRAINABLE_BLOCKS, head_epochs=HEAD_EPOCHS, epochs=EPOCHS)` (frozen and unfrozen policies, selected on validation against epoch 0) → `pipe.evaluate` on validation and test with the comparison (evaluation) → before/after depth maps with `aligned_abs_rel` and a preview PNG (inference) → `pipe.save_artifact` → `DepthAnythingPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** `predict` emits relative inverse depth with no score and no threshold; AbsRel and δ1 are computed only after a per-image affine alignment inside 0.6..350 m with the far cap stated; the selection rule is the lowest validation AbsRel; no acceptance threshold ships.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the constant prior, the vertical-gradient prior and the zero-shot checkpoint are scored on the same 8 test views as the selected policy, per-domain and per-view AbsRel are printed beside every mean, the selection rule is stated (lowest validation AbsRel, the checkpoint competing as epoch 0) and the notebook asserts only that the checkpoint and the selected model beat both priors — a gain over the checkpoint is the question, not an assertion; every metric is labelled as one seeded split of one small corpus with no dispersion estimate (one view = an eighth of a mean).
- **Split integrity (SPL1–SPL8):** the split is seeded, drawn by whole scans per domain and view-disjoint by decoded-pixel digest; validation selects the epoch and policy and the test split is used for nothing but the final evaluation, the before/after render and the reload-parity check; the notebook states that real data must be split by capture session, scan or device.
- **Ceilings (VAL6):** `MIN_IMAGE_SIDE` (14), `MAX_IMAGE_SIDE` (4,096), `MAX_ASPECT_RATIO` (4.0), `EVAL_DEPTH_RANGE_M` (0.6..350), the record bounds (4..2,000), the valid-pixel floor (5 %), the depth ceiling (1,000 m) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one image refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user records flow through the same validation, seeded group-disjoint split (the loader refuses a `records.csv` row without a non-empty `group`, so the group-disjoint guarantee holds for BYOD as it does for the sample; `require_group=False` is the explicit opt-out), priors, zero-shot scoring, policy ladder, evaluation, preview, export and reload cells; files inside the uploaded zip are decoded from the archive, never extracted. The expected schema and the privacy guidance — RGB-D captures of homes, workplaces or people are restricted data — are stated in the Prerequisites and in Section 4, and the training records table is written to `outputs/depth_anything_depth_estimation_train.csv` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
